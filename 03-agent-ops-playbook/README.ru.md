# 03 — agent-ops-playbook

**Книга паттернов: что на самом деле ломается, когда LLM-агенты работают 24/7, и паттерны, которые это исправляют.** Написано по производственным инцидентам, а не по теории.

> Это сердце репозитория. Инструменты приходят и уходят; эти паттерны — накопленные шрамы.

## Что вы получаете

- `README.md` — план глав (паттерны, кратко изложенные ниже)
- `incidents/` — обезличенные вскрытия, каждое: симптом → доказательства → первопричина → исправление → предотвращение → урок
  - `530k-token-session.md` — тихий убийца бюджета (траты ×7, а «модель отупела» оказалось болотом контекста)
  - `gateway-alive-but-dead.md` — гонка DB-sidecar, из-за которой живой процесс превратился в мёртвого бота
- `decision-trees.md` — конкретные чек-листы: «агент тормозит?», «баланс падает?», «дайджест пропал?», «бот мёртв, но процесс жив?», «сообщение задублировалось?»

## Главы

### 1. Роли и экономика — «босс и работники»
Основной диалог работает на *умной* модели; cron-задачи и шаблонные задания — на *дешёвой*; вспомогательные вызовы (сжатие, заголовки, проверка, vision) — на самой дешёвой из способных. Оценку апгрейдов делайте только по DM — экстраполяция на весь трафик завышает стоимость в ~3 раза. Контроллер не должен быть той же моделью, что и работник.

### 2. Проектирование оповещений и дайджестов
**Тишина = OK.** Пустая дельта → одна короткая строка или ничего. **Оповещение сверху**: сначала отклонение, крупно, с планом Б. Контентные дайджесты многословны; сервисные дельты молчат. Дедупликация через непрерывность; запуск LLM пропускайте через дешёвый детектор изменений (нет diff → нет вызова LLM).

### 3. Гигиена сессий
Ежедневный сброс + сброс по простою (~4 ч); память/профиль/навыки сохраняются; сбрасывается только история. Порог компакции настроен так, чтобы сессии сжимались до того, как станут непосильными по цене; вспомогательное сжатие привязано к дешёвому провайдеру. Гигантские сессии — тихий убийца бюджета №1 и причина №1 эффекта «модель отупела».

### 4. Мультиролевые агенты без хаоса
Один профиль = один SOUL.md = полная память роли. Роли общаются через **файлы, а не сообщения** (доктор пишет файл лимитов, который повар читает перед каждым планом; очередь вопросов в одну строку; ноль межролевых пингов). Границы закреплены дважды: списки игнорируемых тем на уровне шлюза + явное правило в SOUL. Специалисты запускаются по запросу и никогда не отвечают сами.

### 5. Кто следит за сторожами
Каждый сторож наблюдается *другим* уровнем, который переживает самого сторожа. Проверки свежести должны знать реальное расписание каждой задачи. Под наблюдением не всё — исключения являются задокументированной возможностью, а не недосмотром.

### 6. Недопонимание при голосовом вводе
Транскрипции искажают термины предметной области. Относитесь к каждому названию из транскрипта как к гипотезе; сверяйте с фактическими запасами/рецептами пользователя, прежде чем читать лекции. Агенты уверенно галлюцинируют о собственных запасах пользователя — неловко и предотвратимо.
