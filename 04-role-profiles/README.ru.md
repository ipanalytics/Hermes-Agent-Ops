# 04 — role-profiles

**Мультиролевая агентная архитектура на едином шлюзе: один бот, N профессиональных персон, у каждой — своя память, своя тема и свои границы.**

## Что вы получаете

- `template/SOUL.md.example` — аннотированный скелет мастер-промпта: список секций, который делает роль самодостаточной (стиль работы, предпочтения, правила измерений, инвентарь, оборудование, проверенные рецепты с маркерами статуса, **жёсткие границы**, защита от повторения прошлых ошибок, заметки о голосовых подводных камнях).
- `template/config.yaml.example` — закрепление моделей за ролями: дешёвая — для исполнителей, осторожная — для доктора, *третья* модель — для оператора (ревьюер ≠ исполнитель), вспомогательные вызовы (aux) на самом дешёвом подходящем провайдере, настройки гигиены сессий + компакции (compaction).
- `docs/routing.md` — таблица решений «кто чем занимается» + протокол передачи дел (handover) + намеренные исключения.

## Правила, благодаря которым это работает

1. **Один профиль = один SOUL.md.** Весь мир роли живёт в одном мастер-промпте + её собственных файлах данных/рецептов. Никакого разрозненного контекста.
2. **Роли общаются через файлы, а не через сообщения.** Доктор *пишет* файл лимитов; шеф-повар *читает* его перед каждым планом. Вопросы уходят одной строкой в файл-очередь, который разбирает другая роль. Ноль межролевых пингов, полный журнал аудита.
3. **Границы обеспечиваются дважды**: списки игнорирования тем (ignore-lists) на уровне шлюза (роль буквально не видит приватную тему) + явное правило в SOUL («ты не медик; никаких диагнозов»).
4. **Специалисты не отвечают самостоятельно.** Они запускаются по требованию через координатора. Профиль с собственным шлюзом отвечал бы сам по себе — включайте такой режим, только когда он действительно нужен.
5. **Побеждает последнее сообщение.** Когда человек противоречит старым данным SOUL, новая инструкция получает приоритет и фиксируется, чтобы вопрос не разбирался заново.
