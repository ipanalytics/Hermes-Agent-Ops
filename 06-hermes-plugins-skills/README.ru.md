# 06 — Плагины и навыки Hermes

**Упаковка проверенных решений в виде плагинов, навыков (skills) и cron-рецептов Hermes — и их передача в upstream (основной проект).**

## Что вы получаете

- `skills/one-shot-reminder/SKILL.md` — полноценный навык: паттерн напоминаний с фиксированным текстом без затрат на LLM (скрипт + одноразовое задание без агента (no-agent) + автоотключение), с описанием подводных камней часовых поясов и привязки (anchoring).
- `cron-recipes/monitor-gated-digest.md` — будить LLM только когда что-то изменилось (дешёвый фильтр на базе детектора изменений + дедупликация с учётом непрерывности): наблюдение за ценами, списки отслеживания релизов.
- `cron-recipes/watchdog-chain.md` — поддержание работы долгоживущих сервисов без root-прав (rootless) с помощью watchdog'ов планировщика; правила привязки (anchoring) и отсоединения (detachment), проверенные в продакшене.

## Принципы проектирования

- **Промпты должны быть самодостаточными**: задание cron выполняется в новой сессии без контекста чата — всё, что ему нужно, передаётся в промпте или в файле, на который он ссылается.
- **Скрипты хранятся как файлы**, никогда не в виде inline-heredoc (сканеры политик их блокируют).
- **Наблюдатели `no_agent` ничего не выводят, когда всё исправно** — пустой stdout = ноль доставок = ноль затрат. Одно это правило делает мониторинг практически бесплатным.
- **Тестируйте одноразовые задания (one-shot) ручным запуском**, прежде чем ставить их в реальное расписание.
- **Путь в upstream**: всё достаточно универсальное должно попадать в сам проект Hermes (PR в документацию, функции ядра); остальное остаётся в виде плагинов сообщества. Для каждой упакованной части следует указывать, к какой из этих категорий она относится.

## Почему это важно

У Hermes есть настоящая аудитория в open-source. Пакет для «продвинутых пользователей» (power-user) с рецептами, проверенными в бою, превращает личные «шрамы» в ценность для сообщества — и приносит звёзды родительскому репозиторию.
