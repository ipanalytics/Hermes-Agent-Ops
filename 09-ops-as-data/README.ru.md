# 09 — ops-as-data

**Запланированные задания как живая документация: перестаньте писать таблицу наблюдения вручную, генерируйте её из списка заданий.**

> Документация всегда расходится с реальностью — пока документация не начнёт генерироваться ИЗ реальности.

## Что вы здесь получаете

- `cron_exporter.py` — рендерит markdown-таблицу наблюдения из JSON-списка заданий: когда запускается каждое задание (cron в человекочитаемом виде), с LLM-агентом или без него, куда доставляет результаты, примечания и кто за ним следит. Детерминированный, бесплатный, пригодный для CI.
- `jobs.example.json` — схема входных данных, с пятью реалистичными заданиями (дайджест, страж, отслеживание цены, зависящее от монитора, медиа-дайджест на выходные, разовое напоминание).

## Замыкаемый цикл

1. Список заданий — единственный источник истины (планировщик уже хранит его — экспортируйте).
2. Экспортёр рендерит таблицу → закоммитьте её рядом с ops-документацией (`05-cron-of-crons`).
3. Правила свежести едут вместе с генерируемым футером (Mon–Fri в субботу = корректно; задание без LLM, не печатающее ничего = исправно).
4. Подключите это к обходу оператора: любое расхождение между сгенерированной таблицей и предыдущим коммитом — необъявленное изменение расписания.

## Связка

- `07-fresh-prompt-linter` оберегает *промпты* агентских заданий; этот — *документацию расписания*.
- Экспорт автоматически наполняет матрицу «кто за кем следит» в `05-cron-of-crons`.
