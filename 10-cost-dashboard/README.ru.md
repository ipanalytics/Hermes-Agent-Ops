# 10 — cost-dashboard

**Посмотрите, куда ушли деньги: однофайловая HTML-панель из базы данных usage — расходы по дням, по провайдерам и топ сессий, съевших ваш бюджет.**

> `01-agent-wallet-guard` говорит, КОГДА горят деньги. Это говорит, ГДЕ.
> Guard измеряет факт (баланс провайдера); dashboard атрибутирует его
> (по сессии/дню/провайдеру). Guards + атрибуция = вы перестаёте гадать.

## Что здесь есть

- `cost_dashboard.py` — читает ту же таблицу usage в sqlite, что и guard, и рендерит самодостаточную HTML-страницу: без сервера, без JS-фреймворков, один файл, который можно открыть где угодно или отдавать статически.

## Что она показывает

- **Суммарные оценочные расходы** за окно (период), сессии с использованием, самый загруженный день.
- **Расходы по дням** — столбцы; обрыв в 7 раз — характерный признак сессии, вышедшей из-под контроля.
- **Топ сессий по оценочной стоимости** — id сессии, провайдер, число вызовов, токены кэша. Сессия, вышедшая из-под контроля, — наверху (сортировка по токенам чтения из кэша — честный порядок: попадания в кэш доминируют в трафике агента и являются признаком №1 контекстного болота).
- **По провайдерам** — где на самом деле проходит граница aux vs conversation.

## Оценки vs измеренные балансы

Цены на токены — оценки на основе прайс-листов (переопределяются через `--prices`). Об этом говорит подвал страницы:
dashboard — для *атрибуции*, wallet-guard — для *факта*. Никогда не выставляйте счета по
dashboard, никогда не отлаживайтесь только по guard.

## Связка

- guard `01` присылает алерт с id сессии-виновника → открыть dashboard → сбросить эту сессию.
- Схема usage общая с `01`, поэтому оба инструмента попадают в одну и ту же БД.
