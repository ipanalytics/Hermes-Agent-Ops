# 10 — cost-dashboard

_English version: [README.md](README.md)_

**Один HTML-файл из базы использования агента. Расход по дням, по провайдерам, по самым дорогим сессиям. Открывается в любом браузере, сервер не нужен.**

Hermes — домашний ИИ-агент, который живёт на моём сервере, — болтает с несколькими провайдерами
круглосуточно. Каждый вызов записывается: таймстамп, идентификатор сессии, провайдер, число
входных токенов, выходных токенов и дешёвых кеш-токенов (повторяющийся префикс, который
провайдер тарифицирует в десятки раз дешевле свежего текста). Всё это складывается в таблицу
SQLite под названием `session_model_usage`, одна строка на сессию. `cost_dashboard.py` читает
эту таблицу и рендерит самодостаточную HTML-страницу: сумму расходов за последние N дней,
график по дням, разбивку по провайдерам и десятку самых дорогих сессий.

Место в серии простое. Модуль 01 (`agent-wallet-guard`) — это **тревога**: он сообщает, что
бюджет горит. Этот модуль — **карта**, которую я открываю сразу после, чтобы увидеть, в какой
день, через какого провайдера и какая сессия жгла деньги. Тревога называет проблему; панель
указывает на комнату.

## Зачем это нужно

Тревога кошелька без разбивки — половина ответа. Знать «сегодня превышен лимит» не говорит мне,
взорвалась ли смена модели расходы, не стал ли резервный провайдер тихо главным, или одна
убежавшая сессия съела сорок процентов недельного бюджета, пока остальной агент работал
нормально. Читать сырой JSONL глазами — пропустить очевидное: столбец, который нависает над
соседями, провайдера, чей кусок вырос месяц к месяцу, идентификатор сессии, который три дня
подряд торчит наверху таблицы.

Поднимать ради панели отдельный web-сервис я не хочу, и тащить за панелью сборщик JavaScript
тоже. Один запуск `cost_dashboard.py --db state.db --out cost.html`, по крону раз в день,
открываю файл, когда сработала тревога кошелька, или на еженедельной ревизии.

## Что внутри

- `cost_dashboard.py` — читает `session_model_usage` из базы SQLite, накладывает карту цен
  (встроенные умолчания плюс необязательный JSON-оверрайд) и пишет одну HTML-страницу. Страница
  использует инлайн-CSS и ноль JavaScript; один файл открывается в любом браузере.
- `examples/` — заготовка; принесите свою базу.

## Что я вижу на странице

HTML состоит из четырёх блоков, стоящих столбиком:

1. **Карточки в шапке.** Оценка суммы за окно (по умолчанию 14 дней), число сессий с любым
   использованием, самый загруженный отдельный день.
2. **Расход по дням.** По горизонтальной полоске на день, отнормировано к самому загруженному
   дню. Полезно, чтобы заметить всплеск, ещё не дотянувший до дневного лимита.
4. **Топ сессий по оценочной стоимости.** До десяти строк, отсортировано по убыванию: идентификатор
   сессии (первые 24 символа), провайдер, число вызовов, кеш-токены, оценка в долларах. Это
   таблица, которая говорит мне: «сессия `abc123…` отвечает за треть расхода, у `secondary`, с
   14M кеш-токенов — разбирать».
8. **По провайдерам.** По строке на провайдера с его долей от оценочной суммы. Здесь видно
   тихую смену умолчания: кусок, который внезапно сравнялся с долей основного провайдера или
   превысил её.

В подвале страницы — пометка, что это *прейскурантные* оценки (прайс из `--prices`, или
встроенный `DEFAULT_PRICES` для `primary` / `secondary` / `aux`, если оверрайд не задан). Модуль
01 измеряет **факт** через API баланса провайдера; эта панель измеряет **атрибуцию**, чтобы я
мог действовать. Два числа должны совпадать до нескольких процентов; если не совпадают — виноват
прайс.

## Как я этим пользуюсь

```bash
python3 cost_dashboard.py --db ~/.hermes/state.db --out ~/dashboards/cost.html
```

Три ключа делают работу:

- `--db` — путь к базе SQLite использования. Скрипт открывает её только для чтения
  (`file:...?mode=ro`).
- `--days` — длина окна, по умолчанию 14. Работает от 1 до «вся история»; на длинных окнах
  полоски по дням просто становятся плотнее.
- `--out` — путь HTML, по умолчанию `cost-dashboard.html`.
- `--prices` — необязательный JSON-файл, перекрывающий встроенные умолчания; нужен, когда мои
  реальные цены расходятся с прейскурантом или когда я добавил нового провайдера.

Гоняю его по крону каждую ночь — чистый SQL, без вызовов модели, ничего не стоит — и открываю
файл в браузере, когда срабатывает тревога кошелька или в рамках еженедельной ревизии. HTML
настолько мал, что кидается и в чат тоже.

## Ограничения

- Схема фиксирована. Скрипт читает одну таблицу, `session_model_usage(session_id,
  billing_provider, first_seen, cache_read_tokens, input_tokens, output_tokens, reasoning_tokens,
  api_call_count)`. Если другое развёртывание логирует использование иначе, SQL придётся
  подогнать; рендерер остаётся прежним.
- Оценки честны настолько, насколько честна карта цен. `--prices` перекрывает встроенные
  умолчания, и я обновляю её, когда провайдер объявляет о смене. Баланс со стороны провайдера
  (модуль 01) остаётся правдой для вопроса «сколько я на самом деле потратил».
- Атрибуция честна настолько, насколько полно логируется. Локальный прогон модели, не попавший
  в `session_model_usage`, здесь невидим. Если я забуду добавить строку для нового inference-пути,
  панель будет тихо занижать расход.
- Это отчёт, а не управление. Ничто в HTML не останавливает расход. Модуль 01 тревожит;
  модуль 19 (`cost-governance`) реально ставит на паузу самые дорогие задания. Панель —
  прослойка между ними: она говорит мне, *что настроить* в страже, чтобы он смотрел.
