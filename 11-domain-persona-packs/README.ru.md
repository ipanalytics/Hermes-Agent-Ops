# 11 — domain-persona-packs

_English version: [README.md](README.md)_

**Готовые к копированию профессиональные роли для агентов: повар с инвентарём, врач с файлом ограничений, аналитик с источниками — роль за 10 минут, а не за неделю.**

> Каркас нескольких ролей (`04-role-profiles`) — это движок; эти пакеты —
> картриджи. Каждый пакет = разделы SOUL.md + привязки config + файловые мосты +
> границы, и каждый пакет я собрал по реальной роли, которая работает каждый
> день, и обезличил.

## Что значат слова (на случай, если открыл репозиторий впервые)

Hermes — мой домашний ИИ-агент, долгоживущий помощник на моём собственном сервере: делает за
меня бытовые задачи (дайджесты, слежение за ценами и техникой, дайджесты здоровья, мониторинг
своих же сбоев) и пишет для себя скрипты. **Роль** (или **профиль**) — одна профессиональная
персона, которая живёт поверх того же бота: врач, повар, оператор — у каждого своя память,
свои файлы и свои жёсткие границы. **SOUL.md** — это мастер-промпт одной роли, длинный
Markdown-файл, который описывает, как она думает, что знает, что будет и не будет делать.
**Каркас нескольких ролей** в `04-role-profiles` — это движок, который превращает SOUL.md и
конфиг в работающую роль: задаёт, какие разделы должны быть в каждом SOUL.md, и закрепляет за
каждой ролью свой уровень модели. **Пакет** — это одна такая полностью заполненная роль,
упакованная так, чтобы я мог подложить её в новое развёртывание и получить работающего
профессионала за время чтения одного файла. **Шлюз** — единая точка входа, которая
направляет каждое входящее сообщение нужной роли по тому, в каком чат-топике оно пришло;
**границы** — правила, не дающие одной роли отвечать на вопросы вне её компетенции. **Файловые
мосты** — файлы, которые одна роль пишет, а другая читает: врач пишет файл ограничений, повар
читает его перед любым планом.

## Зачем нужны эти пакеты

Модуль `04` даёт мне движок: шаблон, раскладку конфига, таблицу маршрутизации. Это то,
что делает роль **возможной**. Эти пакеты — то, что делает роль **быстрой**: каждый
пакет — это рабочий SOUL.md, рабочий конфиг, рабочий набор мостов, уже отточенный на
роли, которая каждый день работает у меня дома, обезличенный и выложенный сюда, чтобы
я не собирал заново повара, врача или оператора при каждой переустановке. Разница
заметна, когда нужна пятая роль: только с движком «хочу сомелье» — это неделя
писанины; с нужным пакетом «хочу сомелье» — это «подложил шаблон, заполнил SOUL.md по
образцу, привязал к шлюзу» — десять минут.

Пакеты ещё закрепляют закономерность, которую я усвоил на живых ролях: роль, которая
импровизирует с формой своих данных — это роль, которая дрейфует. Пакет повара
фиксирует форму файла инвентаря (в наличии, на руках, доесть), форму списка рецептов
(маркеры `[VERIFIED]` / `[PRINCIPLE]` / `[NEW]`), форму файла моста (ограничения,
которые пишет врач). Эта фиксированность — то, что делает роль аудируемой.

## Пакеты (растущие)

### Повар — инвентарь кладовой, проверенные рецепты, медицинские ограничения, считываемые из файла

- **SOUL**: как готовит именно эта кухня. Соль отмеряется в точных количествах на каждом
  шаге — «на глаз» не работает; готовность определяется по физическим признакам (цвет,
  корочка, жидкость), а не по минутам.
- **Данные**: файл инвентаря («сейчас в наличии — доесть» против «нет в наличии»),
  список рецептов с маркерами `[VERIFIED]` / `[PRINCIPLE]` / `[NEW]` и особенности
  техники. `[VERIFIED]` — рецепт доведён до конца именно на этой кухне; `[NEW]` — в
  меню не идёт без прогона.
- **Границы**: никакой импровизации вокруг файла врача; рецепты только из
  утверждённого списка, если человек не скажет иначе.
- **Мосты**: перед каждым планом читает файл ограничений врача (соль, аллергены), после
  каждого приёма пищи записывает остатки обратно в инвентарь записью со сроком.

### Врач — медикаменты и добавки; отвечает только по запросу, записывает файл расписания

- **SOUL**: никаких диагнозов за пределами компетенции, никаких дозировок «на глазок».
  Врач пишет файл ограничений, который читает повар, и трогает файл расписания только
  когда что-то изменилось. Всё, что за пределами компетенции — формулировка «обратитесь к
  специалисту», а не догадка.
- **Данные**: общий файл ограничений/расписания и текущее состояние добавок. Файл
  ограничений — это и есть мост: в нём потолок соли, аллергены, запрещённые сочетания
  с причинами по каждому пункту, в форме, которую повар читает без знания медицины.
- **Границы**: за пределами компетенции — формулировка «обратитесь к специалисту», и
  никакого спама: обновление только по факту изменения.

### Аналитик / оператор — периодический обход на отдельной модели

- **SOUL**: проверяющий — не исполнитель; бриф обхода самодостаточен (см. `05`); когда
  всё нормально — одна строка вывода, 🔴 на каждое происшествие; свежесть данных
  сверяется с расписанием обхода. Исполнитель, оценивающий собственный результат, —
  это слепое пятно, которое измеряет модуль `21`; роль оператора — ответ на это, другие
  глаза над теми же данными.
- **Границы**: никаких разрушительных действий без команды владельца; о том, что
  заблокировала политика, — сообщать, а не обходить её исподтишка.

## Анатомия пакета (что означает «иметь пакет»)

1. Разделы `SOUL.md`, готовые к слиянию в шаблон из `04`. Слияние структурное: разделы
   роли заполнены и соблюдают порядок разделов шаблона, чтобы загрузчик ролей шлюза мог
   подставить их без переписывания.
2. Привязки `config`: уровень модели (дешёвая/основная), частота, топик доставки.
   Каждая роль несёт явную привязку модели, а не дефолт — повар на дешёвой, врач на
   осторожной, оператор на третьей, проверяющей.
3. `bridges/`: файлы, которые роль читает и пишет, с владельцами. У каждого моста
   объявлен владелец, список читателей и форма. Мост без владельца дрейфует; мост с
   владельцем остаётся фиксированным.
4. `boundaries`: списки игнорирования шлюза + правило SOUL, оба слоя. Список
   игнорирования — жёсткая стена, правило SOUL — мягкая. Обе стены нужны; одной
   недостаточно — в каждой есть дыры.

## Связанные модули

- **04-role-profiles** — движок, в который эти пакеты вставляются. Шаблон, таблица
  маршрутизации, правила границ.
- **05-cron-of-crons** — бриф обхода оператора генерируется из списка задач этого

  обхода.
