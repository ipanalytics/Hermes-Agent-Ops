# Пример — классификатор безопасности shell-команд

Набор задач, лежащий в основе правил `bash_guard` из модуля 15, выраженный в виде задачи оптимизации промпта (prompt optimization): 29 размеченных команд (включая обходы с обфускацией кавычками и с прогоном через декодер по конвейеру), метрика = точное совпадение по SAFE/UNSAFE.

```bash
bash run.sh                       # 60 metric calls, writes report.json
MAX_CALLS=150 bash run.sh --write # write the improved prompt back over seed_prompt.txt
```

**Прочитайте результат.** С сильной целевой моделью этот набор уже решается исходным (seed) промптом (в нашем запуске: seed ≈ 1.0 на валидационном разбиении, исследовано три кандидата, ни одно изменение не прошло проверку). Это корректный результат и причина, по которой обёртка печатает `No prompt change survived validation`, а не фальшивое улучшение: оптимизация промпта окупается только там, где узкое место — сам промпт, а не модель. Подставьте более слабую task LM (`--task-lm openrouter/<small-model>`) или более сложный размеченный набор — и та же команда выдаст настоящий diff.
