# 17 — model-slot-bakeoff

**Прайс-лист — это доллары за миллион токенов. Он не говорит, сколько стоит один запрос.**

> Модель с рассуждениями (reasoning model) может сжечь в шесть раз больше выходных токенов,
> чем обычная, на том же самом промпте, поэтому модель, более дешёвая за токен, в итоге
> оказывается более дорогой за задачу — и более медленной. Единственный способ узнать это —
> прогнать реальную работу слота через обе и посмотреть на счёт, на часы и на то, был ли
> ответ действительно корректным.

## Что вы получаете

- `bakeoff.py` — прогоняет один набор задач через N моделей-кандидатов, оценивает каждый
  ответ по скрытому тесту и записывает JSON-отчёт плюс сводную таблицу.
- `examples/slot-check/` — набор из двух задач со скрытыми тестами и три кандидата на слот
  для кодирования (обычная модель-кодер, модель с рассуждениями и та же модель с пониженным
  усилием рассуждений (reasoning effort)).
- `tests/test_bakeoff.py` — офлайн-тесты для оценивания, загрузки и путей ошибок.

## Что измеряется для каждого кандидата

| Сигнал | Почему он в отчёте |
|---|---|
| `passed` | решает скрытый тест, а не собственное заявление модели — кандидат никогда не видит тест |
| `avg_cost_per_task_usd` | стоимость, выставленная шлюзом за этот вызов, включая токены рассуждений |
| `completion_tokens` | показывает, *почему* модель, дешёвая за токен, дорога за задачу |
| `served_by` | маршрутизация — не всегда то, что вы запрашивали; это тот апстрим (upstream), который ответил |
| `avg_latency_s` | слот на критическом пути пользователя расплачивается за медленного кандидата на каждом запросе |
| `tool_call_ok` | с `--with-tools`: модель, которая никогда не выдаёт вызов инструмента, не может занимать агентский слот |

## Как использовать

```bash
python3 bakeoff.py --candidates candidates.json --tasks tasks.json --with-tools
```

API-ключ читается из `OPENROUTER_API_KEY` (переменная окружения или `~/.hermes/.env`).
Направьте `BAKEOFF_API_URL` на любой совместимый с OpenAI эндпоинт, чтобы измерить другой
шлюз.

Список кандидатов — тестируемая модель, опциональная привязка к апстриму и опциональные поля
запроса; именно здесь вариант с `reasoning_effort` становится отдельным кандидатом:

```json
[
  {"label": "incumbent", "model": "vendor/model-a"},
  {"label": "challenger", "model": "vendor/model-b", "provider": "FirstPartyCloud"},
  {"label": "challenger (low effort)", "model": "vendor/model-b", "extra": {"reasoning_effort": "low"}}
]
```

Набор задач — промпт плюс тест, который оценивает ответ. Оценивание запускает блок кода
модели против теста во временной директории, поэтому задачи должны быть проверяемыми:

```json
[
  {"name": "flaky-input",
   "prompt": "Write a Python function `pick(items, key, k)` ... Answer with one ```python block only.",
   "test": "from solution import pick\nassert pick([{'n': 1}], 'n', 1) == [{'n': 1}]\nprint('OK')"}
]
```

## Измеренный пример

`examples/slot-check`, две оцениваемые задачи, один прогон (все три кандидата обслужены одним
и тем же first-party-апстримом, все три прошли оба скрытых теста):

| кандидат | прохождение | средняя задержка | средняя стоимость / задача | выходные токены / задача |
|---|---|---|---|---|
| обычная модель-кодер | 2/2 | 3.0 с | $0.00077 | 435 |
| модель с рассуждениями, усилие по умолчанию | 2/2 | 134.0 с | $0.01655 | 12 938 |
| модель с рассуждениями, низкое усилие | 2/2 | 13.8 с | $0.00234 | 1 796 |

Корректность идентична, различие в том, сколько слот стоит за запрос, — 21×, и 45× по
задержке, и всё это потрачено на токены рассуждений, которые модель без рассуждений никогда
не производит. Снижение усилия у модели с рассуждениями возвращает её к стоимости в 3× от
обычной модели при четверти токенов. Тот же набор задач в другой день или с другой смесью
задач может сдвинуть эти числа — вот почему существует этот стенд (harness), а не таблица цен
из прайс-листа.

## Три отказа, которые это ловит, а прайс-лист скрывает

1. **Токены рассуждений.** Выходные токены — дорогая половина счёта, и модели с рассуждениями
   тарифицируются за них. Сравнивать цены за токен между моделью с рассуждениями и моделью
   без них — значит сравнивать не ту цифру.
2. **Маршрутизация.** `served_by` сообщает апстрим, который реально ответил. Модель, чьи
   единственные апстримы находятся вне списка разрешённых провайдеров аккаунта шлюза, падает
   с `HTTP 404: No allowed providers are available for the selected model`, хотя каталог её
   содержит и статус её эндпоинта исправен — тело ошибки называет и апстримы модели, и
   список разрешений (allow-list), и это единственное место, где сказано, почему модель нельзя
   вызвать. Задайте привязку через `"provider": "<name>"`, когда узнаете, какой апстрим нужен.
3. **Вызовы инструментов.** Для агентского слота поддержка вызовов инструментов — жёсткое
   требование, а не бонус. `--with-tools` проверяет её одним запросом.

## Ограничения

- Несколько задач — это smoke-тест, а не бенчмарк. Он отвечает на вопрос «какой кандидат дешевле и при этом корректен для *этого* слота», а не «какая модель умнее».
- Стоимость — это то, что гейтвей (gateway) сообщает по каждому вызову; попадания в кэш и скидки на стороне провайдера не моделируются.
- Задержка меняется вместе с нагрузкой на апстрим (upstream): сравнивайте кандидатов в рамках одного запуска, а не по разным дням.
- Тестовая обвязка (harness) исполняет написанный моделью Python-код, чтобы оценить его. Держите скрытые тесты без зависимостей и запускайте её в одноразовом окружении, если тестируемые модели не заслуживают доверия.
