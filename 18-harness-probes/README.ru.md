**Обвязка агента меняется каждый день, и никто не замечает момента, когда правка тихо ломает то,
что работало вчера.**

> Расписания сдвигаются, промпты правятся, сторожевые скрипты рефакторятся, таблицы маршрутизации
> переписываются. Тестов у этой поверхности обычно нет: агент отвечает, кроны стреляют, а регрессия
> всплывает через три дня — пропавшим дайджестом или повторной закачкой. Это и есть недостающий
> приёмочный гейт.

## Обзор

`probes.py` прогоняет набор детерминированных проверок — они описаны в JSON, код для новой пробы
не нужен — по артефактам, которые агент обязан производить: свежие отчёты, непустые очереди,
разбираемые файлы состояния, сторожевые скрипты, которые молчат, пока всё в пределах лимита,
дайджесты с минимальным числом пунктов, выводы заданий без учётных данных. Каждый прогон пишет
отчёт в JSON. Первый принятый прогон становится базой.

Дальше правка обвязки — это две команды:

```bash
python3 probes.py run      # до правки
python3 probes.py check    # после правки — код 1 при регрессии
```

`check` падает только на *регрессии*: проба, которая проходила в базе, а теперь упала. Падения,
которые были и раньше, печатаются, но не блокируют, — известный больной угол не парализует гейт.

## Как это работает

| Режим | Что происходит |
|---|---|
| `run` | выполняет все пробы, пишет `data/probes_last.json`, печатает падения, код 1 при любом |
| `check` | то же плюс сравнение с `data/probes_baseline.json`; регрессии дают код 1 |
| `accept` | записывает текущий результат как базу — осознанное действие, а не побочный эффект |
| `list` | печатает набор проб: идентификатор, вид, описание |

Виды проб:

| Вид | Что проверяет |
|---|---|
| `file_fresh` | файл есть, моложе N часов, не меньше M байт |
| `files_no_empty` | в каталоге очереди нет файлов нулевого размера |
| `json_keys` | JSON разбирается, обязательные вложенные ключи на месте, элементов не меньше N |
| `script_silent` / `script` | команда завершилась с кодом 0 и пустым / непустым / любым выводом |
| `text_match` | шаблон встречается в файле не меньше N раз (например, три карточки в дайджесте) |
| `secrets_clean` | в последних N файлах каталога нет строк, похожих на учётные данные |

Все пути считаются от `HARNESS_HOME` (по умолчанию `~/.hermes`), поэтому один и тот же набор
работает и на ноутбуке, и на сервере, и в контейнере.

## Быстрый старт

```bash
git clone <этот репозиторий> && cd 18-harness-probes
export HARNESS_HOME=$HOME/.hermes
cp examples/probe_set.example.json "$HARNESS_HOME/data/probe_set.json"
$EDITOR "$HARNESS_HOME/data/probe_set.json"       # укажите свои пути к артефактам
python3 probes.py run
python3 probes.py accept                           # зафиксировать хорошее состояние
```

В планировщик — как сторож, раз в час достаточно:

```cron
55 * * * * /path/to/probes_check.sh   # молчит, когда всё в порядке; при регрессии печатает её
```

## Почему база — отдельный файл

Набор проб, который дрейфует незаметно, хуже отсутствия проб. Принятый результат лежит в
`probes_baseline.json` и пишется только явным `accept`, поэтому определение «работает» меняется
осознанно. Приём взят из исследований о правке навыков и обвязки с учётом регрессий
(arXiv 2605.29668: изменение допускается, только если отложенный набор проб не показывает
ухудшения), и я подтвердил это на практике: ценность не в наличии тестов, а в отказе принимать
правку, которая меняет одну зелёную галочку на другую.

## Выходные данные

`data/probes_last.json`:

```json
{
  "checked_at": "2026-09-13T16:55:02",
  "total": 7,
  "passed": 7,
  "probes": [{"id": "report-fresh", "kind": "file_fresh", "ok": true, "why": "2166 б, 2.1 ч назад"}]
}
```

Коды возврата: `0` — норма, `1` — падение (или регрессия в режиме `check`), `2` — нет набора проб.

## Эксплуатационные замечания

- Пробы должны быть детерминированными. Проба, в выводе которой есть метка времени, будет
  выглядеть изменившейся каждый прогон; метки времени — в отчёт, не в проверки.
- `secrets_clean` печатает имя файла, но не найденное значение, чтобы лог прогона сам не стал
  каналом утечки.
- Одна проба — одно обещание, видимое пользователю. Если проба падает по причине, которую вы
  принимаете навсегда, это решение: правьте пробу, затем `accept`.
- Набор должен прогоняться меньше чем за минуту; медленные пробы в спешке начинают пропускать.

## Границы применимости

В границах: детерминированная проверка собственных артефактов агента и сторожевых скриптов.
Вне границ: оценка качества ответов модели (для измерения того, что пропускает автоматика, —
модуль 21), нагрузочное тестирование, юнит-тесты прикладного кода.

## Сценарии

- Агенты по расписанию, где никто не смотрит каждый прогон.
- Сторожевые скрипты (лимиты бюджета, контроль доставки), которые обязаны молчать в норме.
- Конфигурации на нескольких машинах, где одна и та же обвязка живёт на сервере и дома.
- Любой конвейер, у которого отказ выглядит как «файл не появился», а не «процесс упал».

## Ограничения

- Пробы проверяют то, что кто-то записал. Обещание, которое никто не занёс в набор, они не заметят.
- Они проверяют артефакты, а не замысел: дайджест с тремя карточками пройдёт, даже если карточки
  не про то.
- База — это снимок: после осознанного изменения поведения непринятая база покажет регрессию,
  которая на самом деле — решение.

## Развёртывание

Зависимостей, кроме стандартной библиотеки Python, нет. Запускать из любого планировщика: обёртка
возвращает код возврата, поэтому подойдёт любой супервизор, понимающий ненулевой код.

## Отказ от ответственности

Пробы уменьшают радиус поражения от правок обвязки, но не делают агента безопасным для работы без
присмотра. Сканер секретов — эвристика против случайностей, а не средство защиты.
