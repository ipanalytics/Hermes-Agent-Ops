**Лимит бюджета, который действует сам, и метрика, которая считает сделанную работу, а не токены.**

> Оповещения рассчитаны на то, что кто-то не спит. Агент по расписанию жжёт деньги в 04:00 так же
> охотно, как в полдень, а «запросы» — не та единица, против которой можно потратить бюджет. Здесь
> три инструмента, закрывающие этот разрыв: лимит, который ставит на паузу самые дорогие задания,
> отчёт «доллары за успешную задачу» по ролям и статическая проверка, которая не даёт префиксу
> инструментов агента тихо отрасти обратно.

## Обзор

| Инструмент | Задача |
|---|---|
| `budget_guard.py` | суммирует токены за сутки из журнала и при перерасходе ставит на паузу N самых дорогих заданий; `--resume` возвращает их |
| `cost_per_outcome.py` | соединяет журнал, список заданий и прайс, печатает цену успешного прогона по ролям |
| `toolsets_audit.py` | находит задания, в промпте которых упомянут инструмент, недоступный по их набору |

## Как работает budget_guard

Журнал — это JSONL: одна запись на вызов модели с полями `ts`, `job_id`, `prompt_tokens`,
`completion_tokens`, необязательным `error`. Страж суммирует текущие сутки UTC, сравнивает с
`cap_tokens_per_day` и при перерасходе сортирует задания по расходу и ставит на паузу верхние N,
выполняя шаблон команды:

```json
{"cap_tokens_per_day": 12000000, "top_n": 3,
 "pause_command": "hermes cron pause {job_id}",
 "resume_command": "hermes cron resume {job_id}"}
```

Три свойства важнее самого порога:

- **Без каскада.** Он действует один раз в сутки (`action_date` в собственном файле состояния).
  Поставить на паузу тройку, а через час следующую тройку — так страж бюджета превращается в аварию.
- **Обратимы только его решения.** `--resume` возвращает те задания, которые остановил он сам, и
  никогда — те, что человек остановил по своей причине.
- **Молчит, когда всё в порядке.** Пустой вывод означает «под лимитом»; супервизор может считать
  пустой прогон успехом.

```bash
python3 budget_guard.py --dry-run     # показать план, ничего не трогать
python3 budget_guard.py --resume      # вернуть то, что он остановил
```

## Как работает cost_per_outcome

Прайс отвечает, сколько стоит токен; бюджет тратится против стоимости законченной работы. Ошибки
тоже стоят денег, поэтому остаются в числителе и исключены из знаменателя:

```
media   ok 34/41  $1.86  →  $0.055 за успех
mail    ok 28/28  $1.15  →  $0.041 за успех
infra   ok 96/99  $0.90  →  $0.009 за успех
```

Роли — это регулярные выражения по именам заданий, поэтому отчёт следует вашему именованию, а не
фиксированной таксономии. Наблюдение за этим числом в течение недели показывает, какая правка
действительно окупилась: смена модели, дешевле за токен, может проиграть за задачу, если чаще падает.

## Как работает toolsets_audit

Ограничение списка инструментов укорачивает фиксированный префикс на каждом шаге — реальная
экономия и тихий отказ, если урезанный инструмент был несущим. Проверка читает список заданий и
карту «набор → регулярное выражение» и сообщает о каждом промпте, который ссылается на инструмент,
недоступный заданию. Так я нашёл опечатку (`files` вместо `file`), неделями тихо отключавшую
файловые операции у задания: никакой ошибки, просто отсутствующая возможность.

## Быстрый старт

```bash
cp examples/budget_guard.json ~/.hermes/data/budget_guard.json
cp examples/prices.json .
python3 toolsets_audit.py --jobs ~/.hermes/cron/jobs.json --map examples/toolset_map.json
python3 cost_per_outcome.py --jobs ~/.hermes/cron/jobs.json \
    --audit ~/.hermes/cron/usage_audit.jsonl --prices examples/prices.json --window-days 7
```

## Ограничения

- Учёт токенов настолько точен, насколько точен журнал рантайма; обёрнутые и повторные вызовы должны
  записываться отдельно, иначе суточная сумма плывёт.
- Страж останавливает задания, но не переносит их; сочетайте с утренним возвратом в расписание.
- Цена за результат поощряет дешёвые задачи с большим числом прогонов; читайте её по ролям, а не как
  одну общую оценку.
- `toolsets_audit` лексический: находит упоминания, а не фактическое использование.
