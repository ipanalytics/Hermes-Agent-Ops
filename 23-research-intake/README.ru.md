**Читать литературу как корпус, который вы считаете, а не как ленту, которую листаете, — и вести
журнал того, что действительно внедрили.**

> Большинство «трендовых» отчётов сравнивают то, что индекс показал на этой неделе, с тем, что он
> показал на прошлой: каждый раз другая выборка, поданная как направление. Этот каталог идёт другим
> путём — выкачивает набор по протоколу харвестинга, считает термины локально в равных окнах и
> хранит каждую идею, пережившую неделю, в журнале с первым шагом, метрикой и датой отсечения.

## Обзор

| Файл | Задача |
|---|---|
| `oai_harvest.py` | пройти набор OAI-PMH с токеном продолжения, дописать JSONL, посчитать термины офлайн |
| `direction_digest.py` | доли терминов по равным окнам, сдвиг помечается только если пережил сравнение |
| `backlog.md` | схема журнала и правила, не дающие ему превратиться в музей |

## Почему OAI-PMH и локальный подсчёт

Поисковый API отвечает на вопрос «что индекс считает релевантным», по одной странице, с лимитами,
не имеющими отношения к вашему профилю использования. Я измерил это напрямую: API запросов arXiv
возвращал ошибку лимита даже на тривиальный запрос из одного термина, причём с двух разных сетей —
то есть ограничение не по IP и ротацией выхода не лечится. У протокола харвестинга замысел
противоположный: `ListRecords` с набором и токеном продолжения обходит весь набор, по одному запросу
за раз, и OAI-эндпоинт arXiv отдавал тысячи записей в неделю там, где API запросов не отвечал вовсе.

Подсчёт затем идёт локально, по выкачанному тексту, вашими регулярными выражениями:

```bash
python3 oai_harvest.py --set cs:cs.AI --days 7 --out data/cs.AI.jsonl
python3 oai_harvest.py --count data/cs.AI.jsonl --terms examples/terms.json
```

Именно это делает сравнение по неделям честным: одна и та же форма корпуса, одни и те же шаблоны, без
меняющегося под низом ранжирования. Доли печатаются вместе с числом записей, потому что неделя с
удвоенным числом записей раздувает любое абсолютное значение.

## Журнал

`backlog.md` описывает схему, которую я держу рядом с корпусом: `status` из candidate / trying /
adopted / rejected, `first_step`, достаточно малый, чтобы сделать его на этой неделе, `metric`, дата
`kill_by` и обязательное `reason` для отказов. Два правила делают основную работу:

- **Равные окна, доли вместо абсолютов** — иначе загруженная неделя читается как тренд.
- **У отказов остаётся причина** — «пробовали, метрика не двинулась» самая переиспользуемая строка в
  файле и единственное, что не даёт одной и той же идее возвращаться каждый квартал.

## Быстрый старт

```bash
cp examples/terms.json .
python3 oai_harvest.py --fixture examples/oai_fixture.xml --out data/example.jsonl   # офлайн-проверка
python3 oai_harvest.py --set cs:cs.AI --days 7 --out data/cs.AI.jsonl
python3 oai_harvest.py --count data/cs.AI.jsonl --terms examples/terms.json
python3 direction_digest.py --corpus data/cs.AI.jsonl --terms examples/terms.json --weeks 5 --out digest.md
```

## Ограничения

- Наборы пересекаются, записи объявляются повторно; дедупликация по идентификатору закрывает общий
  случай, но не каждое перекрёстное попадание.
- Подсчёт терминов измеряет лексику, а не качество: термин может вырасти потому, что больше работ
  используют это слово в аннотации.
- OAI-PMH вежлив по замыслу: полный обход набора занимает минуты и несколько запросов. Это цена
  стабильного корпуса, и при одном прогоне в неделю она мала.
