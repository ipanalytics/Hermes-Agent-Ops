**Самая дорогая схема в агенте по расписанию — модель, которая каждый прогон сама забирает,
разбирает, дедуплицирует и ранжирует, а в конце пишет два абзаца.**

> Обратная схема даёт тот же результат за долю стоимости: скрипт собирает и ранжирует, модель только
> оформляет. В этом каталоге — форма такой замены, инструмент, который находит следующего кандидата, и
> числа двух реальных замен, включая ту, что убрала 44% расхода токенов развёртывания.

## Обзор

| Файл | Задача |
|---|---|
| `collector.py` | эталонная форма: нормализовать → дедуплицировать по устойчивому ключу → ранжировать по явным правилам → артефакт и одна строка итога |
| `token_audit.py` | ранжировать задания по токенам, оценить по объёму входа и плотности инструкций, дать список кандидатов |

## Инверсия в одной таблице

| | Модель делает всё | Скрипт собирает, модель оформляет |
|---|---|---|
| за прогон | забрать, разобрать, дедуплицировать, ранжировать, написать | прочитать артефакт, написать |
| контекст | каждая скачанная страница, каждый кандидат | только выбранные элементы |
| режим отказа | тихий: правдоподобный текст после неудачной загрузки | скрипт выходит с ненулевым кодом; оформлять нечего |
| стоимость | тысячи входных токенов за прогон | сотни |

Две замены из развёртывания, из которого выросла эта серия:

- **Задание слежения**, которое опрашивало источник и по каждому элементу принимало решение: 53,7 млн
  токенов за измеряемое окно, 44% всего расхода, около 331 тыс. входных токенов за прогон. После
  замены на скрипт, который опрашивает, фильтрует и пишет состояние: повторяющийся расход стал нулевым,
  потому что рассуждать больше не о чем.
- **Три задания дайджестов** примерно по 557 / 941 / 841 тыс. входных токенов за прогон, каждое
  перечитывало и переранжировало одни и те же источники. После замены — один сборщик плюс короткий
  промпт оформителя: сбор детерминирован, модель пишет по одному предложению на карточку.

## Что принадлежит скрипту

Четыре вопроса по порядку. «Да» на любой из них означает, что шаг не должен жить в промпте:

1. Два прогона с одинаковым входом *должны* дать одинаковый выход? (дедупликация, ранжирование, формат)
2. Отказ описывается кодом возврата оболочки? (загрузка, разбор, проверка)
3. Результат потребляет код, а не читает человек? (файлы состояния, очереди)
4. Нужно суждение о данных перед вами, а не о мире? (фильтрация по правилу)

Что остаётся модели: решать, что важно, писать для человека и решать, когда эскалировать. Инструмент
поиска кандидатов использует объём входа и маркеры инструкций как приближение, потому что обе величины
измеримы до замены и сравнимы после.

## Быстрый старт

```bash
python3 collector.py --input examples/feed.json --state seen.json --out cards.md --top 3
python3 token_audit.py --jobs jobs.json --audit usage_audit.jsonl --top 10
```

## Ограничения

- Сборщик — это код, и он может ошибаться так, как промпт не может: он не заметит, что источник
  сменил форму, если это не проверять. Сочетайте замену с модулем 18.
- Список кандидатов эвристический. Маленькое задание с плотным промптом конвертировать не стоит;
  большое задание с тривиальным промптом — может быть, стоит.
- Замены на практике односторонние: когда задание стало скриптом, способность рассуждать о краевых
  случаях переезжает в код, где её нужно записать.
