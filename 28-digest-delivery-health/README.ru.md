Скрипт анализирует здоровье доставки дайджестов, сравнивая реальные запуски cron-задач с ожидаемыми расписаниями, предоставляя отчеты о покрытии доставок ежедневных дайджестов.

## Обзор

Я запускаюсь как cron-задача для мониторинга состояния доставки дайджестов за последние 7 дней. Я анализирую историю выполнения из логов аудита и сравниваю реальные запуски с ожидаемыми шаблонами расписания, создавая отчеты о покрытии, периодах тишины и ошибках для различных типов дайджестов.

## Как это работает

Я считываю историю выполнения из файла лога JSONL и сопоставляю реальные запуски с ожидаемыми шаблонами расписания для разных типов дайджестов. Я рассчитываю коэффициенты покрытия, обнаруживаю ошибки и безответные реакции, а также отслеживаю показатели производительности, такие как максимальное время выполнения. Я сравниваю данные текущей недели с предыдущей неделей, чтобы определить тенденции.

## Быстрый старт

```bash
# Установите необходимые переменные окружения
export HERMES_AUDIT_LOG=~/.hermes/cron/usage_audit.jsonl
export HERMES_JOBS_FILE=~/.hermes/cron/jobs.json
export HERMES_DIGEST_HEALTH_STATE=~/.hermes/data/digest_health_state.json

# Запустите скрипт
python3 digest_health.py
```

## Использование

Скрипт не принимает аргументы командной строки. Он использует переменные окружения для поиска файлов конфигурации:

- `HERMES_AUDIT_LOG`: Путь к файлу лога аудита (по умолчанию: `~/.hermes/cron/usage_audit.jsonl`)
- `HERMES_JOBS_FILE`: Путь к файлу конфигурации заданий (по умолчанию: `~/.hermes/cron/jobs.json`)
- `HERMES_DIGEST_HEALTH_STATE`: Путь к файлу состояния (по умолчанию: `~/.hermes/data/digest_health_state.json`)

## Вывод

Я вывожу форматированный отчет, показывающий:
- Статистику покрытия для каждого типа дайджеста (реальные/ожидаемые запуски)
- Количество ошибок и количество безответных реакций
- Индикаторы производительности (наихудшее время выполнения)
- Индикаторы тенденций (сравнение с предыдущей неделей)
- Визуальные индикаторы статуса (красный/желтый/зеленый)

## Ограничения

- Требует правильно отформатированные логи аудита в формате JSONL
- Чувствителен к временной зоне (использует UTC для вычислений)
- Зависит от последовательных ID заданий в конфигурации
- Исторический анализ ограничен 7-дневными окнами
