Этот модуль проверяет влияние изменения политики сжатия контекста в Hermes Agent. Он собирает базовые метрики до изменения политики, затем сравнивает шаблоны использования после изменения, чтобы определить, улучшилась ли новая политика или ухудшилась в потреблении ресурсов.

## Обзор

Я запускаю этот модуль для оценки изменений политики сжатия контекста в Hermes Agent. Модуль устанавливает базовый уровень во время периода до изменения, затем измеряет изменения в ежедневных затратах, соотношениях сжатия и эффективности кэширования после внедрения новой политики сжатия. Я анализирую такие метрики, как ежедневные затраты, использование модели сжатия и соотношения чтения кэша к входным токенам, чтобы предоставить четкий вердикт об эффективности политики.

## Как это работает

Я собираю данные об использовании из базы данных Hermes до и после изменения политики сжатия. Мой процесс включает:

1. Установление базовых метрик за настраиваемый период до изменения
2. Запись точной временной метки изменения политики
3. Измерение тех же метрик после изменения в течение периода наблюдения
4. Сравнение ежедневных затрат, использования сжатия и эффективности кэширования
5. Предоставление четкого вердикта о том, улучшилось или ухудшилось ли изменение

Я храню свое промежуточное состояние в файле JSON для отслеживания прогресса эксперимента и избежания дублирующих сообщений.

## Быстрый старт

```bash
# Установите переменные окружения для вашего эксперимента
export CHANGE_TIMESTAMP=$(date +%s)  # Временная метка изменения политики
export COMPACT_MODEL_NAME="glm-5.3-flash"
export BASELINE_DAYS=3
export OBSERVE_DAYS=3

# Запустите проверку
python3 compaction_effect_check.py
```

## Использование

Модуль принимает конфигурацию через переменные окружения:

- `HERMES_DB_PATH`: Путь к базе данных Hermes (по умолчанию: `~/.hermes/state.db`)
- `COMPACT_STATE_FILE`: Путь к файлу состояния (по умолчанию: `~/.hermes/data/compaction_experiment.json`)
- `BASELINE_DAYS`: Дни для сбора базовых данных (по умолчанию: 3)
- `OBSERVE_DAYS`: Дни наблюдения после изменения (по умолчанию: 3)
- `COMPACT_MODEL_NAME`: Имя модели для отслеживания сжатия (по умолчанию: `glm-5.3-flash`)
- `CHANGE_TIMESTAMP`: Unix временная метка изменения политики

Запустите скрипт несколько раз во время эксперимента. Он будет молчать до завершения периода наблюдения, затем выведет результаты один раз.

## Выводы

Мой вывод включает:

- Сравнение ежедневных затрат (до и после)
- Сравнение затрат на сжатие
- Количество вызовов сжатия
- Соотношение кэш/входные токены
- Четкий вердикт о том, было ли изменение полезным

## Ограничения

Я требую доступ к базе данных Hermes с статистикой использования. Моя эффективность зависит от наличия достаточных периодов базовой и наблюдательной линии для установления надежных метрик. Я отслеживаю только модели, идентифицированные по шаблону имени модели сжатия. Эксперимент предполагает одно изменение политики в течение окна наблюдения.
