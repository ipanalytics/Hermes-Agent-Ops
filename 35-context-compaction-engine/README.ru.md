_English version: [README.md](README.md)_

![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue)

Движок сжатия контекста для Hermes Agent: длинная сессия заменяется **рабочим состоянием** — задача, решения, ограничения, точные значения, следующий шаг, — а не пересказом разговора. Вместе с ним идёт стенд приёмки, который судит сжатие по тому, можно ли после него довести задачу до конца.

## Зачем он создан

Движок, который работал до него, вырезал устаревшие результаты инструментов и никогда не сокращал текст пользователя и ассистента. За неделю настоящих сессий видно, где эта конструкция ломается: «текстовый пол» растёт с каждым циклом (в трёх длинных сессиях 43K → 139K, 91K → 240K, 175K → 359K токенов), доля освобождаемого падает с каждым запуском (89% → 55%, 76% → 20%, 63% → 8%), а одна сессия на 200K-окне вообще перестала сжиматься — 0% освобождения, контекст прижат к потолку.

Причин две, и обе — конструкция, а не настройка:

1. **Сжатие включалось по объёму.** «Перевалило за порог — режем». Никто не решал, нужна ли ещё работа из этого окна: законченный заход исследования и недописанный файл выглядели одинаково.
2. **Результат никто не измерял.** Освободить 90% контекста легко, если не жалко нить задачи: выбросить середину, оставить последние ходы — и число красивое. Единственным сигналом качества было «как сессия себя чувствует дальше», а замечалось это через дни.

Поэтому модуль — замена, а не заплатка: сжимаем **работу**, а приёмку ведём **по продолжению**.

## Что он делает

1. **Когда сжимать.** Не только у стенки. Сжатие срабатывает и на границе задачи: пользователь заговорил снова, а контекст уже больше ~60% порога — значит предыдущий заход закончен и устарел (`should_compress_preflight`). Жёсткий порог остаётся предохранителем (`should_compress`).
2. **Что сохранять.** Вместо пересказа процесса — рабочее состояние: задача, решения и почему, ограничения, **точные значения дословно** (пути, идентификаторы, ключи, команды, тексты ошибок, числа), сделанное, открытое, следующий шаг и что перепроверить после сжатия. Пишет дешёвая вспомогательная модель; движок никогда не просит модель-арбитр писать прозу.
3. **Как продолжать.** Блок состояния встаёт сразу за защищённой головой; последние `tail_tokens` свежей работы остаются дословно. Блок помечен, поэтому на следующем цикле он не вырезается, а **переносится**: секции прошлого блока разбираются и вливаются в новое состояние *без просьбы к модели пересказать их заново* — именно там и гибли точные значения.
4. **Чем проверять.** Каждое сжатие журналируется (`data/autocompact_decisions.jsonl`), а приёмку ведёт `resume_eval.py`: знает ли сессия, которая видит только сжатый контекст, чем она занималась.

## Блок состояния

Блок — весь продукт сжатия. Точные значения здесь не свалка, а окно вытеснения: свежее сверху, самое старое уходит первым, а потолок намеренно вдвое больше того, что даёт один цикл, — поэтому значения прошлого блока переживают следующий цикл целиком.

```
## Задача
- <что делаем и почему>
## Решения
- <решение> — <почему>
## Ограничения
- <чего делать нельзя>
## Точные значения
- путь: /srv/app/bin/collect.py
- файл: releases-collect.timer
- команда: systemctl list-timers --all
## Сделано
## Открыто
## Следующий шаг
## Проверить после сжатия
```

Заголовки секций — часть контракта: следующий цикл разбирает этот же текст обратно в состояние, поэтому движок и стенд обязаны называть их одинаково. Пример блока — в `examples/state_block.md`.

## Быстрый старт

```bash
# 1. Кладём движок туда, где хост ищет движки контекста, и выбираем его
cp autocompact.py ~/.hermes/plugins/autocompact/__init__.py
hermes config set context.engine autocompact

# 2. Ставим ручки (см. examples/engine_config.yaml)
hermes config set compression.threshold_tokens 250000
hermes config set compression.autocompact_preflight_ratio 0.6
hermes config set compression.autocompact_tail_tokens 25000
```

## Настройка

| Ключ (в секции `compression:`) | По умолчанию | Смысл |
|---|---|---|
| `threshold_tokens` | `250000` | Жёсткий триггер: у стенки сжимаем в любом случае |
| `autocompact_preflight_ratio` | `0.6` | Доля порога, при которой сжатие может сработать на границе задачи |
| `autocompact_target_ratio` | `0.45` | Во что целимся после сжатия |
| `autocompact_tail_tokens` | `25000` | Свежая работа, которая остаётся дословно, в токенах |

## Приёмка: судим по продолжению

`resume_eval.py` работает на **копии** базы состояний (живую отказывается читать) и мерит три вещи:

- **A. Точные значения.** Вырезанная сжатием часть механически сканируется на значения, которые нельзя восстановить: пути, id сессий, хеши, адреса, имена юнитов и файлов, команды, числа с единицами. Мусор из веб-выдачи отбрасывается. Отдельно считается **свежий край** окна — по нему работает следующий ход.
- **B. Жизнь сессии и анти-храповина.** Цикл 1 сжимает первую половину; потом приходит вторая (работа продолжалась) и срабатывает цикл 2. Освобождение и выживание значений не должны падать, а в контексте обязан остаться **ровно один** блок состояния — не штабель.
- **C. Живой опрос (`--live`).** Модель составляет вопросы по вырезанной части с золотыми ответами; свежая сессия, видящая **только сжатый контекст**, отвечает; третья судит по золоту.

```bash
cp ~/.hermes/state.db /tmp/state_copy.db          # живая база не читается
PY=$(ls -d ~/.hermes/tools/python-*/bin/python3 | head -1)
HERMES_HOME="$HOME/.hermes" "$PY" -I resume_eval.py \
  --db /tmp/state_copy.db --session <session_id> --cycles 2 --live
```

## Измеренный результат

Одна настоящая сессия (901 сообщение, 405 318 токенов): после сжатия 59 сообщений, 31 527 токенов — освобождено 92.2%, блок состояния 13 090 знаков, ошибок структуры нет.

На копии сессии в 4000 сообщений, два цикла с продолжением работы между ними:

| Цикл | Токенов до | Токенов после | Освобождено | Свежих значений уцелело | Перенесено из прошлого блока |
|---|---|---|---|---|---|
| 1 | 783 419 | 40 329 | 94.9% | 95.4% из 65 | — |
| 2 | 995 896 | 34 363 | 96.5% | 74.2% из 93 | 95.4% из 65 |

По одному блоку состояния на цикл, ни одного сироты «вызов ↔ результат», живой опрос — 8/8 после первого цикла и 8/8 после второго. Офлайновые пробы в `tests/` идут за секунду и покрывают то, что решает судьбу значений: разбор и рендер секций, перенос прошлого блока, окно вытеснения, контракт «нечего сжимать — вернуть тот же объект», путь при недоступной модели.

## Ограничения

- Движок — плагин рантайма Hermes и импортирует из него (`agent.context_engine`, `agent.model_metadata`, `agent.compression_marker`, `agent.auxiliary_client`); это не самостоятельная библиотека. Тесты подставляют эти четыре модуля заглушками.
- Блок состояния пишется по-русски, и заголовки секций — интерфейс между циклами. Переносить его на другой язык нужно вместе с `_TITLE_TO_KEY`, `_render_state` и стендом.
- Значения из глубины вырезанной части в блок **не попадают** — это осознанный контракт: блок держит ограниченное окно, и шапка блока прямо говорит, что старое перечитывается поиском по сессии, а не берётся из памяти.
- Качество упирается в модель сжатия: если она отвечает прозой вместо JSON, движок уходит на детерминированный путь — структура сохраняется, повествование теряется.
- `--live` тратит настоящие вызовы моделей на опрос: это ворота релиза, а не проверка на каждое сжатие.
