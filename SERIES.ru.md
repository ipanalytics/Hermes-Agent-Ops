# Карта серии — как папки продолжают друг друга

Новые модули расширяют старые; таблица ниже фиксирует, что на чём строится. Вскрытия инцидентов в `03` — причина существования большинства остальных папок.

## Нити

| # | Папка | Продолжает / продолжается |
|---|---|---|
| 01 | agent-wallet-guard (алерты о расходе) | → **10** cost-dashboard (показывает, *куда* ушёл расход) |
| 02 | gateway-supervisor (восстанавливает шлюз) | питается рецептами watchdog из **06**; путь эскалации задокументирован в инцидентах **03** |
| 03 | agent-ops-playbook (рубцовая ткань) | линтер **07** предотвращает один класс его инцидентов; **13** документирует другой (голосовой ввод); decision-trees.md — общий мозг |
| 04 | role-profiles (движок) | **11** persona-packs — патроны для этого движка; **12** добавляет тематические стены |
| 05 | cron-of-crons (кто за кем следит) | **09** ops-as-data генерирует его watch-table (таблицу наблюдения) из списка задач |
| 06 | hermes-plugins-skills (упаковка) | **08** session-housekeeping тоже поставляется в виде skills |
| 07 | fresh-prompt-linter | охраняет каждый промпт агентской задачи до того, как тот попадёт в расписания 05 |
| 08 | session-housekeeping | жизненный цикл, который предотвращает инцидент «сессия на 530K токенов» из 03 |
| 09 | ops-as-data | сохраняет документацию 05 достоверной |
| 10 | cost-dashboard | делает оповещения 01 объяснимыми |
| 11 | domain-persona-packs | причина использовать 04 |
| 12 | topic-routing | стены, которые делают многоролевость 04 безопасной |
| 13 | voice-input-hypotheses | исправление на стороне агента для целого класса ошибок из 03 |
| 14 | agent-data-intake | паттерн unit-модулей из 02, применённый к периферийным приёмникам; объяснён инцидент приёма данных из 03; контракт спула (spool), который должен поставлять каждый отправитель на стороне устройства |
| 15 | agent-tool-guardrails | позиция внешнего суждения (outside-judgement) из **02**, обращённая на команды и worktree; охраняет то, что на самом деле делают промпты, одобренные **07**; lane-половина сочетается с собственной изоляцией worktree в Hermes |
| 16 | gepa-skill-tuner | цикл починки после **07**: линтер блокирует плохой промпт, тюнер переписывает один из них на размеченном трафике; его наборы задач — ровно то, что порождают гейты **15** и инциденты **03** |
| 17 | model-slot-bakeoff | шаг измерений, лежащий в основе фиксации моделей в **04**: слот стоит столько, сколько стоят его задачи за один вызов, а прогоны оптимизации из **16** наследуют этот выбор |

## Порядок чтения

1. **Начните с 03** — инциденты (10 минут) объясняют, почему существует каждая остальная папка.
2. **Возьмите 04 + 11**, чтобы развернуть их собственные роли.
3. **Разверните 01 + 10**, прежде чем доверять чему-либо из этого реальные деньги.
4. **Пропускайте каждый cron-промпт через 07** и генерируйте документацию с помощью 09.
5. **Наблюдайте за всем** с помощью 05 и позвольте 02/06 поддерживать сервисы в рабочем состоянии.

## Правила контрибуции

Каждая папка владеет своим README и своими артефактами. PR, затрагивающий папку, обновляет соответствующую строку карты. Новый код поставляется вместе с тестом, который его проверяет, а README перечисляет реальные файлы.
